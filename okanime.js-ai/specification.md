# 仕様書

## 概要
OKファイルの効果がわかるアニメーションを行うJavascript + HTML

## 構成
- VanillaJS
- 1 HTMLファイル (JavascriptやCSSは同梱)
- 画像リソースは 「resources」 ディレクトリ内

## 画面仕様
- **HTMLタイトル**: `OK File Animation` とする。
- **全体レイアウト**:
    - コンテンツ全体の表示領域を幅 `1000px` に設定する。
    - その領域をブラウザウィンドウの中央に配置（センターリング）する。

画面は上下2つのペインで構成する。

### 1. 設定ペイン (上部)
- **OKファイル**: チェックボックス
    - ラベル: 「OKファイル」
    - OKファイルを利用したアニメーションか、利用しないアニメーションかを切り替える。
- **アニメーション速度**: スライダー
    - ラベル: 「アニメーション速度」
    - 範囲: 0.0 ～ 5.0倍速 (0.1刻み)
    - デフォルト: 1.0倍
    - **影響範囲**: この設定は、JOBの処理時間、待ち時間、および全てのアニメーションの時間など、アプリケーション内の時間経過が関わる全ての動作に対して乗数として適用される。
- **操作ボタン**:
    - **開始ボタン**: JOB① Generator と JOB③ Projector のタイマーを開始し、アニメーション全体の動作を開始する。
    - **停止ボタン**: JOB①とJOB③の次のタスク実行を停止する。現在実行中の処理（生成やコピー）は完了まで続行されるが、新規のタスクは開始されなくなる。
    - **リセットボタン**: 全てのJOBタイマーを停止し、`temp` および `upload` 領域のファイルアイコンを全てクリアする。アニメーション全体を初期状態に戻す。

### 2. アニメーションペイン (下部)
左から以下の3つのエリアを、それぞれ間隔をあけて横に並べて配置する。

- **temp (送信元)**
    - 最大6つのファイルアイコンを配置する。
    - アイコンの配置順は以下の通り、左上から右下への2列3行とする。
      ```
      [①] [②]
      [③] [④]
      [⑤] [⑥]
      ```
    - この領域内のファイルが `upload` エリアに移動して空きができた場合、後続のファイルが空いた位置に0.5秒程度のスライドアニメーションで詰めるように移動する。
        - 例: アイコン `①` のファイルが移動した場合、アイコン `②` が `①` の位置へ、`③` が `②` の位置へ...と順番に移動する。
- **upload (送信先)**
    - 最大6つのファイルアイコンを配置する。
    - アイコンの配置順は `temp` 領域と同様。
    - この領域内のファイルが `display` エリアに移動して空きができた場合、後続のファイルが空いた位置に0.5秒程度のスライドアニメーションで詰めるように移動する。
- **display (投影先)**
    - `upload` 領域から投写されたファイルアイコンを常時表示するための領域。
    - **この領域には常に1つのファイルアイコンのみが表示される。**
    - JOB③が実行されるたびに、表示されるアイコンが新しいものに更新される。
    - 領域名の表示デザインは他の2つの領域（temp, upload）と同様に揃えられている。
    - JOB③ Projector の待ち時間中は、この領域にリングインジケーターが表示される。

## ファイルアイコン仕様
ファイルやその状態を視覚的に表現するためのアイコンに関する仕様。

### 1. 基本デザイン
- 紙を模した、一般的に使われるファイルのアイコンとする。
- アイコンの下部に、ファイル名（例: `YYYYMMDD_HHMMSS.bin`）を表示するラベルを配置する。
- ファイルの種類によってアイコンの色を変更する。
    - **通常ファイル (.bin):** 薄緑色。
    - **OKファイル (.ok):** 薄紫色。

### 2. 状態インジケーター
- ファイルの「生成中」および「コピー中」、**「投写中」** の状態を示すため、アイコン内部にリング状のプログレスインジケーターを表示する。
- インジケーターは青色で、時計回りに進むことで進捗（0%〜100%）を表現する。

### 3. 不透明度
- ファイルコピー中、インジケーターの進捗に合わせてアイコン全体の不透明度を変更する。
- 進捗が0%の時に不透明度30%、進捗が100%の時に不透明度100%となるように、進捗に応じて不透明度を線形に変化させる。


## バッチJOB仕様
各JOBの連携と動作は以下の通り。

### 1. JOB① Generator (生成)
- **役割**: `temp` ディレクトリにファイルを生成し、生成したファイルリストをパラメータとしてJOB②を実行する。
- **実行トリガー**: 前のJOB①の処理が完了してから3〜5秒後。
- **生成処理時間**:
    - 通常ファイル: 3〜5秒。
    - OKファイル: 一瞬で完了する。
- **生成ファイル**:
    - 形式: `YYYYMMDD_HHMMSS.bin`
    - OKファイル設定ON時: 同名の `.ok` ファイルも生成する。
- **待ち時間インジケーター**: JOB①の**生成完了後から次の実行までの**待ち時間中は、`temp` 領域にリングインジケーターが表示される。
- **境界条件**: `temp`領域のファイル数が6に達している場合、ファイルの生成はスキップされ、次の実行までの待機処理のみが行われる。

### 2. JOB② Uploader (コピー)
- **役割**: JOB①からパラメータとして受け取ったファイルを `temp` から `upload` へコピーする。
- **アニメーション**:
    - コピー開始時、`upload` 領域の空きスロットに、コピー先のファイルアイコンが生成される。
    - コピー中、`upload`領域に生成されたファイルアイコンでのみ、以下の2つのアニメーションが実行される。
        - **リングインジケーター:** 0%から100%へと進捗する。
        - **不透明度:** 30%から100%へと変化する。
    - コピー元の`temp`領域にあるファイルアイコンに、見た目の変化はない。
    - `temp`領域で発生するファイル移動アニメーションと、`upload`領域で発生するコピーアニメーションは、それぞれ独立して動作し、同期しない。
- **後処理**: コピー完了後、`temp` にある元のファイルを削除する。
- **コピー処理時間**:
    - 通常ファイル (`.bin`): 5〜9秒。
    - OKファイル (`.ok`): 一瞬で完了する。

### 3. JOB③ Projector (投写)
このJOBは独立して `upload` ディレクトリを監視し、以下の仕様で動作する。

- **実行トリガー**: 3秒ごと。
- **投写対象の選定**:
    - 投写処理の開始時、`display` 領域に待ち時間を示すリングインジケーターが表示される。**このインジケーターは次の投写タイミングまでの待ち時間を示す。**
    - `upload` ディレクトリ内から、タイムスタンプが最も古い通常ファイル（`.bin`）を1つ選定する。OKファイル設定の有無に関わらず、常に通常ファイルが投写対象となる。
- **投写処理**:
    - 選定した投写対象のファイルアイコン（インジケーターが100%の状態）を `display` 領域に表示する。
    - `display` 領域に既にアイコンが表示されている場合は、新しいアイコンに置き換える。
    - 投写されるファイルアイコンは `position: static` で中央に配置される。
    - 投写されるのはOKファイルではなく、常に通常ファイルである。
- **後処理 (ファイル削除)**:
    - 投写処理が完了した後、`upload` ディレクトリから以下のファイルを削除する。
        1. 投写対象となったファイル（`.bin`）。
        2. 投写対象ファイルと同名の `.ok` ファイル（存在する場合）。
        3. （矛盾対策）投写対象として選ばれたファイルよりもタイムスタンプが古い、処理されるべきだった他のすべてのファイル。
